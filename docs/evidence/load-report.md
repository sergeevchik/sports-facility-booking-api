# Нагрузочное тестирование — 25.11.2026

Цель: проверить обычный REST-трафик и связь нагрузки с HTTP/бизнес-метриками.
Объект: собственный локальный стенд, http://127.0.0.1:8000, Docker Desktop на Apple Silicon.
Окружение: [environment.json](environment.json), PostgreSQL 17, один Uvicorn worker.
Другие приложения Mac и фоновые Docker-процессы не изолировались: это учебный локальный
замер, а не предельная производительность сервиса.

## Параметры и сценарий

Команда: `python scripts/run_load.py --users 10 --seconds 300`.
Locust 2.47.0, разгон 1 пользователь/с, пауза между задачами 0.2–1.0 с.
Заданный лимит 300 секунд; журнал Locust: 03:53:28–03:58:24 Europe/Moscow.
Лимит времени отсчитывается Locust с учётом инициализации; активный замер около 297 с.
Это закрытая модель нагрузки с фиксированным числом пользователей, не заданным RPS.

Вес задач: поиск доступности 3, список броней 1, создание + отмена 1.
Цикл создания выполняет два HTTP-запроса, поэтому веса задач не равны долям запросов.
Каждый пользователь получает свою площадку: нормальная нагрузка не создаёт
преднамеренные конфликты. При остановке выполняются cleanup и отключение площадки.
Отдельный тест конкурентного конфликта проверяется pytest: 6 запросов, один 201 и пять 409.

Общий p50 — **8 мс**, p95 — **15 мс**, p99 — **18 мс**; максимальная задержка около 49 мс.
Это клиентские измерения Locust, миллисекунды.

## Сопоставление с мониторингом

[Скриншот живого Grafana](grafana-dashboard.png) показывает выход примерно на 20 HTTP
запросов/с и увеличение счётчиков созданий/отмен. Измерения Prometheus — серверные,
гистограмма даёт оценку квантиля по бакетам; её p95 не должен точно совпадать с Locust.

На широком диапазоне скриншота виден предшествующий отдельный эксперимент отказа БД:
краткая задержка и 503 до старта нагрузочного замера. Он не является ошибкой нормального
нагрузочного сценария. Отдельное [подтверждение восстановления](recovery.json).

## Выводы

На выбранной интенсивности все бизнес-сценарии завершались успешно, создания и отмены
согласованы; задержки оставались небольшими. Признаков насыщения при 10 пользователях
не обнаружено. Этот результат не устанавливает максимальную пропускную способность,
не доказывает работу под любой нагрузкой и не заменяет отдельную проверку конкуренции.
Нагрузочный норматив преподавателем не установлен; значения не объявлены критерием оценки.
